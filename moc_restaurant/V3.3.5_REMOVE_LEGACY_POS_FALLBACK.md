# MOC Restaurant v3.3.5 - Remove Legacy POS Menu/Fallback

This update makes `moc_restaurant_menu_items` the ONLY POS menu source.

## Expected behavior

If Menu Management has:
- 3 items -> POS shows 3 items
- 1 item -> POS shows 1 item
- 0 items -> POS shows no menu items

There is no fallback to:
- Config.StarterMenus
- legacy restaurant menu data
- old GetRestaurantMenu data
- cached/default POS items

## What changed

- `moc_restaurant:getPOSMenu` reads only `moc_restaurant_menu_items`.
- `moc_restaurant:getMenu` also reads the same live table for compatibility.
- Legacy `GetRestaurantMenu()` is redirected to the same live table.
- POS open path explicitly uses `getPOSMenu`.
- Order validation uses the same live menu.
- Empty live menu shows:
  `This restaurant has no live Menu Management items configured.`

## Diagnostic

Run in F8:

`mocpossourcecheck <restaurantId>`

If Menu Management is empty, this must print:

`Live Menu Management rows: 0`

and the POS must not show any items.

No SQL update is required from v3.3.4 to v3.3.5.
