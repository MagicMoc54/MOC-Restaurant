# MOC Restaurant v1.5.4 Storage / Freezer Fix

This build preserves the working v1.5.3 POS and fixes restaurant storage.

## qb-inventory
The older client storage code used:
`inventory:server:OpenInventory`

MOC Restaurant now uses the current server-side qb-inventory:
`exports['qb-inventory']:OpenInventory(...)`

## ox_inventory
ox_inventory support remains enabled through:
`exports.ox_inventory:openInventory('stash', stashId)`

## Also fixed
- Freezer/storage prompt hides correctly after pressing E.
- Only the nearest storage location owns the interaction prompt.
- Storage IDs are validated server-side.
- The server verifies that the selected location is actually a Storage or Freezer.

## No SQL change
No SQL migration is required from v1.5.3 to v1.5.4.

## Test
1. Replace your current `moc_restaurant` folder.
2. Restart `moc_restaurant`.
3. Walk to your saved Freezer.
4. Press E.
5. The selected inventory stash should open.
6. Put an ingredient inside.
7. Close it.
8. Reopen it and verify the item is still stored.
