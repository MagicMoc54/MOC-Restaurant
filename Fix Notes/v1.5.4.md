### FIXED_BUILD_NOTES.md

# MOC Restaurant v1.5.0 Fixed Build

This rebuild corrects two problems in the earlier packages:

1. `/mocrestaurant` is now the single restaurant administration entry point.
   Use **Open Builder** inside that menu to place registers, cooking stations,
   storage, manager locations, and drive-thru points.
2. Placement now uses a dedicated in-game placement mode. Select a location
   type, walk to the exact spot, face the desired direction, press **E**, and
   confirm. Press **BACKSPACE** to cancel.
3. The FiveM manifest has been normalized to `fx_version 'cerulean'`.
   Some earlier later-version packages incorrectly contained the release number
   in the fx_version field.

Commands:
- `/moccreate` - create a restaurant.
- `/mocrestaurant` - open administration and the builder.
- `/mocorders` - available in versions that include the order system.

### V1.5.2_FIX_NOTES.md

# MOC Restaurant v1.5.2 POS Fix

## Critical correction
The previous v1.5.1 hotfix accidentally changed:
`fx_version 'cerulean'`
to:
`fx_version '1.5.1'`

That is invalid for FiveM. This version restores:
`fx_version 'cerulean'`
and correctly sets only:
`version '1.5.2'`

## POS fixes
- Register points open the custom NUI POS.
- NUI focus is explicitly enabled.
- The menu payload is sent after focus is established.
- The register `[E] View <Restaurant> Menu` prompt hides while the POS is open.
- The prompt hides when the player leaves interaction range.
- X / ESC / Backspace can close the POS.
- `/mocpostest` opens the first saved register POS directly for troubleshooting.
- Optional F8 debug messages are available if `Config.Debug = true`.

## Testing
1. Completely replace the old `moc_restaurant` folder.
2. Restart the resource or restart the server.
3. Watch the server console to make sure moc_restaurant starts successfully.
4. Walk to the saved register and press E.
5. If needed, run `/mocpostest`.
6. If it still fails, set `Config.Debug = true` and send the F8/client console errors.

No SQL changes are required.

### V1.5.4_STORAGE_FIX.md

# MOC Restaurant v1.5.4 Storage / Freezer Fix

This build preserves the working v1.5.3 POS and fixes restaurant storage.

## qb-inventory
The older client storage code used:
`inventory:server:OpenInventory`

MOC Restaurant now uses the current server-side qb-inventory:
`exports['qb-inventory']:OpenInventory(...)`

## ox_inventory
ox_inventory support remains enabled through:
`exports.ox_inventory:openInventory('stash', stashId)`

## Also fixed
- Freezer/storage prompt hides correctly after pressing E.
- Only the nearest storage location owns the interaction prompt.
- Storage IDs are validated server-side.
- The server verifies that the selected location is actually a Storage or Freezer.

## No SQL change
No SQL migration is required from v1.5.3 to v1.5.4.

## Test
1. Replace your current `moc_restaurant` folder.
2. Restart `moc_restaurant`.
3. Walk to your saved Freezer.
4. Press E.
5. The selected inventory stash should open.
6. Put an ingredient inside.
7. Close it.
8. Reopen it and verify the item is still stored.

### README.md

# MOC Restaurant v1.5.0 — Advanced POS

This ZIP is a cumulative milestone build. It contains the complete resource through v1.5.0.

## Upgrade approach
- Back up your database and current resource first.
- Replace the old `moc_restaurant` folder with this one.
- Import only the SQL upgrade file for the version you are moving to.
- Restart and test that milestone before moving forward.

## Important compatibility note
FiveM servers differ in QBCore forks, inventory APIs, society banking, item definitions, MLO
geometry, and animation resources. Advanced features are deliberately conservative or disabled
by default where server-specific integration is required.

# MOC Restaurant

## Version 1.2.0 - POS / Ordering Foundation

This milestone connects saved restaurant locations to real ordering gameplay.

## What is included

- In-game restaurant creator
- In-game location builder
- Register interaction points loaded from SQL
- Drive-thru speaker menu interaction
- Starter menu seeding
- Customer ordering
- Cash / bank payment
- Server-side menu price validation
- Server-side total calculation
- SQL order creation
- Basic kitchen order queue
- Employee/job authorization for changing order status
- Order progression:
  - pending
  - preparing
  - ready
  - completed

## Requirements

- qb-core
- oxmysql
- ox_lib

Optional / bridge foundation:
- ox_inventory
- qb-inventory
- ox_target
- qb-target

## Fresh Installation

1. Put the `moc_restaurant` folder in your resources folder.
2. Import `sql/moc_restaurant.sql`.
3. Add/verify your resource order:

   ensure oxmysql
   ensure ox_lib
   ensure qb-core
   ensure moc_restaurant

4. Restart the server.

## Updating from v1.1.x

Back up your database first.

Import:

`sql/upgrade_v1.1_to_v1.2.sql`

Then replace the old `moc_restaurant` resource folder with this version and restart.

## First Setup

1. `/moccreate`
2. Create a restaurant and assign its QBCore job.
3. `/mocrestaurant` → Open Builder
4. Place at least one `Register`.
5. Optionally place a `Drive-Thru Speaker`.
6. `/mocrestaurant`
7. Select `Seed Starter Menu`.
8. Walk to the register and press E.
9. Place and pay for an order.
10. Employees with the restaurant job can use `/mocorders` to progress tickets.

## Important Development Notes

This is still a staged development build.

The POS is currently ox_lib based. A custom sleek NUI POS/customer menu is planned for
the polished UI stage.

The kitchen order queue currently advances tickets but does not yet require cooks to
craft the actual food. The next milestone should add:
- recipes
- ingredient validation
- grill/fryer/drink/prep interactions
- item creation
- station animations
- storage/stashes
- order-item completion tracking

## Upgrade Guidance

This release should be installed over the previous MOC Restaurant version in the release sequence. Review the `sql/` folder inside the resource for any SQL upgrade file associated with v1.5.4.
