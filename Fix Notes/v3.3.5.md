### V3.3.2_POS_MENU_SYNC_FIX.md

# MOC Restaurant v3.3.2 - POS Menu Sync Fix

Fixes Menu Management items not appearing in the live POS.

Root cause:
- POS still opened with old callback `moc_restaurant:getMenu`.
- New v3.3.1 `getPOSMenu` callback was not actually used by openNuiMenu.
- New menu query did not return `id`, but the POS JavaScript requires item.id.
- Order validation could still read the legacy menu source.

v3.3.2:
- Uses `moc_restaurant_menu_items` as the single live POS source.
- `getMenu` and `getPOSMenu` now return the same live menu.
- Returns id, item/name, label, category, price.
- POS open path explicitly uses `getPOSMenu`.
- Server order validation uses the same live DB menu.
- Saving a Menu Management item sends:
  "Menu item saved and POS updated."

Diagnostic:
`mocposmenucheck <restaurantId>`

No SQL update is required from v3.3.1 to v3.3.2.

2. Import `sql/moc_restaurant.sql`.

Back up your database first.

Import:

`sql/upgrade_v1.1_to_v1.2.sql`

## First Setup

1. `/moccreate`
2. Create a restaurant and assign its QBCore job.
3. `/mocrestaurant` → Open Builder
4. Place at least one `Register`.
5. Optionally place a `Drive-Thru Speaker`.
6. `/mocrestaurant`
7. Select `Seed Starter Menu`.
8. Walk to the register and press E.
9. Place and pay for an order.
10. Employees with the restaurant job can use `/mocorders` to progress tickets.

# MOC Restaurant v3.2.2 - Menu Management Open Fix

Fixes clicking Business Management -> Menu Management and nothing happening.

The old client callback path has been replaced with an explicit server
request/response.

Expected flow:

Business Management
-> Menu Management
-> "Opening Menu Management..." notification
-> server validates owner/edit permission
-> server loads restaurant menu + recipes
-> client opens:
   - Add / Update Food or Drink
   - Add / Update Recipe
   - Existing Recipes (when any exist)

Diagnostics:

Server:
[MOC Restaurant] Menu Management request...
[MOC Restaurant] Menu Management data ready...

Client F8:
[MOC Restaurant] Rendering Menu Management...

If SQL tables are missing or another server error occurs, the player gets a
visible error notification and the server console prints the error.

No SQL update is required from v3.2.1 to v3.2.2.

### V3.3.4_DEFINITIVE_POS_DELETE_FIX.md

# MOC Restaurant v3.3.4 - Definitive POS Menu Delete Fix

The previous delete patch corrected the server event, but Menu Management did
not actually display the live POS menu rows as removable items.

## New Menu Management layout

Menu Management now shows:

- Add / Update Food or Drink
- Add / Update Recipe

Existing Menu Items
- Burger - $10
- Fries - $5
- Soda - $3

Existing Recipes
- Burger Recipe
- Fries Recipe

Selecting an entry under Existing Menu Items asks for confirmation and deletes
the exact `moc_restaurant_menu_items.id` record used by the POS.

## Delete verification

The server now:

1. Finds the exact restaurant menu row.
2. Deletes it by `restaurant_id + id`.
3. Queries the database again to verify it is gone.
4. Sends `Menu item removed and POS updated.`
5. Refreshes Menu Management.
6. The next POS open reads the updated database menu.

No SQL update is required from v3.3.3 to v3.3.4.
