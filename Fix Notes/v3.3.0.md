### V2.2.9_DELIVERY_RECEIVING_BUILDER_FIX.md

# MOC Restaurant v2.2.9 - Delivery Receiving Builder Fix

Fixes Delivery Receiving not appearing as a placeable builder location.

## Builder
Use:

`/mocrestaurant`
-> Open Builder
-> Select Restaurant
-> Place Location
-> Delivery Receiving

Recommended interaction radius:
`0.75`

## Diagnostic
If needed, run this in F8:

`moclocationtypes`

You should see:
`delivery_receiving = Delivery Receiving`

## Delivery flow
After placing the station:

1. Order ingredients from Business Management.
2. Wait for the order to become READY.
3. Go to the Delivery Receiving station.
4. Press E.
5. Select the ready shipment.
6. Receive the ingredients.

No SQL update is required from v2.2.8 to v2.2.9.

### BUSINESS_MANAGEMENT_DIRECT_OPEN_FIX.md

# MOC Restaurant v2.2.0 - Business Management Direct Open Fix

This replaces the silent client callback path with an explicit server request/response.

When opening Business Management:
1. Client shows `Opening Business Management...`
2. Server receives the restaurant ID.
3. Server validates/creates the owner employee record.
4. Server builds the permission profile.
5. Server pushes the profile back to the client.
6. Client renders the Business Management menu.

If the server cannot build the profile, the player receives an error notification and
txAdmin/server console receives a `[MOC Restaurant] Business Management ERROR...` line.

The physical Manager Station uses the same robust path.

No SQL changes are required for this patch.

### V1.5.4_STORAGE_FIX.md

# MOC Restaurant v1.5.4 Storage / Freezer Fix

This build preserves the working v1.5.3 POS and fixes restaurant storage.

## qb-inventory
The older client storage code used:
`inventory:server:OpenInventory`

MOC Restaurant now uses the current server-side qb-inventory:
`exports['qb-inventory']:OpenInventory(...)`

## ox_inventory
ox_inventory support remains enabled through:
`exports.ox_inventory:openInventory('stash', stashId)`

## Also fixed
- Freezer/storage prompt hides correctly after pressing E.
- Only the nearest storage location owns the interaction prompt.
- Storage IDs are validated server-side.
- The server verifies that the selected location is actually a Storage or Freezer.

## No SQL change
No SQL migration is required from v1.5.3 to v1.5.4.

## Test
1. Replace your current `moc_restaurant` folder.
2. Restart `moc_restaurant`.
3. Walk to your saved Freezer.
4. Press E.
5. The selected inventory stash should open.
6. Put an ingredient inside.
7. Close it.
8. Reopen it and verify the item is still stored.

### LOCATIONTYPES_FINAL_FIX.md

# MOC Restaurant v3.2.1 - Final LocationTypes Fix

This build permanently cleans the `Config.LocationTypes` section.

The final placeable types include:
- Register
- Grill
- Fryer
- Prep Station
- Drink Station
- Dry Storage
- Freezer
- Tray Pickup
- Manager Station
- Drive-Thru Speaker
- Drive-Thru Payment Window
- Drive-Thru Pickup Window
- Delivery Receiving

Ingredient Supplier is intentionally removed because that feature was retired in
favor of Deliveries & Restocking.

Diagnostic command:
`moclocationtypescheck`

Expected:
- Delivery Receiving present: true
- Ingredient Supplier present: false
- No DUPLICATE location-type lines

No SQL update is required for this fix.
